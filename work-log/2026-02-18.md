# 2026-02-18

## Session 17:51

### Goal
Verify and ship the PyMCC multi-account integration for ClaudeCodeUsage, fix Settings not opening in LSUIElement apps, polish the menu bar badge UI, and cut v1.5.0.

### What we did
- **Diagnosed stale install**: app was v1.4.0; MCC commits had landed but `make install` was never run post-merge. Ran `make install` to sync.
- **Fixed Settings window silently not opening**: root cause was `NSApp.sendAction(showSettingsWindow:)` is dropped by macOS in `LSUIElement` apps (no Dock icon/app menu). First attempt: wrapped in `DispatchQueue.main.async` — still failed. Final fix: abandoned SwiftUI's `Settings {}` scene entirely, replaced with a manually managed `NSWindow` hosting `SettingsView` via `NSHostingController`.
- **Menu bar badge — iterative polish**:
  - First pass: inline `NSTextAttachment` image in attributed string — vertical alignment was off, couldn't control precisely.
  - Second pass: switched to `button.image` with `.imageLeading` — macOS handles centering natively; raised to 18pt.
  - Added kern spacer between badge and "5h" text for breathing room.
- **Popover account switcher**: replaced custom circle `Button` rows with a native `Picker(.segmented)` — cleaner macOS look.
- **README**: documented multi-account MCC feature, settings flow, architecture diagram updated with `AccountStore` node, MCC links updated to point to `sasha-computer/pi-multi-claude-code` (found via `gh repo list`).
- **v1.5.0 release**: bumped `Info.plist`, tagged, pushed, created GitHub release with DMG, bumped Homebrew tap.

### Learnings
- `showSettingsWindow:` / `showPreferencesWindow:` NSApp actions are silently swallowed in `LSUIElement` apps — there's no app menu to route them through. Must manage the window manually with `NSWindow` + `NSHostingController`.
- `NSTextAttachment` inline images in menu bar attributed titles have unreliable vertical alignment; using `NSStatusBarButton.image` with `imagePosition = .imageLeading` delegates alignment to AppKit and works correctly.
- `DispatchQueue.main.async` is not sufficient to work around the `LSUIElement` `showSettingsWindow` issue — it only helps with menu dismissal timing, not the routing problem.
